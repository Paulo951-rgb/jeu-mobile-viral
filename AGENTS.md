# AGENTS.md — JunkYardRush (Godot 4 mobile)

Persistent context for AI agents working on this repo.

## Project type
Native Godot 4.x GDScript mobile game. Targets Android (Google Play) and
iOS (App Store). Portrait-first, touch-first, safe-area aware, responsive.

## Non-negotiables
- **Godot 4 + GDScript only.** No HTML5/Flutter/React Native prototypes.
- **Cross-platform by default.** Do not add Android-only features when a
  portable equivalent exists. iOS export must stay valid.
- **No `com.example…` / `com.yourstudio…` in shipped builds.** Identity lives
  in `src/autoload/app_config.gd` + `project.godot` + `export_presets.cfg`.
- **No secrets in source.** `.gitignore` blocks `*.keystore`, `*.jks`,
  `*.p12`, `*.mobileprovision`, `*.env`, `secrets/`. Review signing config in
  any PR.
- **Mobile rendering**: `renderer/rendering_method.mobile="gl_compatibility"`.
- **Min touch target**: `AppConfig.MIN_TOUCH_SIZE_DP` (56dp). Use `TouchButton`
  for interactive controls.
- **Safe area**: wrap screen UI in `SafeAreaContainer`.

## Architecture
- Autoloads (see `project.godot [autoload]`), order matters for init:
  `AppConfig` (tuning/identity + i18n loader) → `GameManager` (state+signals) →
  `AudioManager` (SFX pool + buses) → `HapticManager` (`Input.vibrate_handheld`,
  no-op on desktop) → `SaveManager` (debounced JSON save to `user://`, loads
  AudioManager/HapticManager settings) → `SceneManager` (fade transitions +
  history). AudioManager/HapticManager load BEFORE SaveManager so the saved
  audio/haptics settings aren't clobbered by their `_ready` defaults.
- Scene flow: `BootScene` → `MainMenuScene` → `GameScene` (+ `GameHud`
  CanvasLayer, `process_mode=ALWAYS` so pause overlay stays interactive). HUD
  subscribes to GameManager signals. SceneManager owns a persistent black fade
  CanvasLayer (layer 100, `process_mode=ALWAYS`).
- Gameplay: `JunkItem` (Area2D, falls) emits `body_collected` (overlap with
  player) or `exited_screen` (fell off bottom = miss). Collecting awards
  `SCORE_PER_JUNK`/`COINS_PER_JUNK`; level derives from score
  (`STARTING_LEVEL + score / SCORE_PER_LEVEL`); spawn interval shrinks per
  level. Missing `MAX_MISSED_JUNK` pieces ends the run (`GameManager.end_run`
  → `game_over` signal → HUD overlay → back to menu).
- Controls: touch (mobile) + mouse (desktop) in `GameScene._input`. Pause via
  on-screen button or the `pause` input action (Esc on desktop).

## Build / export
- `export_presets.cfg` ships presets: Android (Debug APK), Android (Release
  AAB), iOS (Debug), iOS (Release), Linux/X11 (desktop debug).
- Android: Gradle custom build, min24/target34, arm64-v8a only, only
  `VIBRATE` permission.
- iOS: must be exported/signed on macOS with Xcode. `.xcodeproj` is the
  Godot export output, not committed.
- Icons: `assets/android/mipmap-*/icon.png`, `assets/ios/AppIcon.appiconset/*`,
  Play Store 512 in `assets/android/playstore/`.
- Output builds go to `export/` (git-ignored).

## Common edits
- Tune gameplay → `src/autoload/app_config.gd` constants.
- Add a scene → register transitions in `SceneManager.goto_scene(...)`.
- Add UI text → add a row to `src/data/translations.csv` and use `tr("KEY")`.
- Bump version → update `VERSION`/`VERSION_CODE` in `app_config.gd`,
  `project.godot`, and the relevant export preset.

## Gotchas
- `.import` files and `.godot/` are regenerated by the editor on open; do not
  hand-edit them. The committed `icon.svg` has no `.import` on purpose — Godot
  creates it.
- `NOTIFICATION_APPLICATION_PAUSED` is the correct mobile background signal
  (not `app_paused`). Used in GameManager and AudioManager.
- Setting a script on a node after adding children does not re-run `_ready`;
  set the script *before* adding to the tree (see `GameScene._make_junk`).
- iOS launch screen is a single brand-colored PNG for now; replace with proper
  art in milestone 6.

## Testing
No automated test harness yet (Godot doesn't ship one). When adding gameplay,
validate on: a low-end Android device, a modern Android phone, and (when iOS
export is available) an iPhone. Verify orientation lock, safe-area insets,
and that haptics respect the user's `HapticManager.enabled` setting.
